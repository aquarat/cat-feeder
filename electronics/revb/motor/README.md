# On-board A4988 motor block — revision B integration handoff

**Block design, 2026-10-24.** The complete 19-placement connection contract is
[circuit.json](circuit.json), generated by [design.py](design.py). Integration
rationale, current envelope, footprint comparison and open power qualification:
[KB motor integration](../../../kb/pcb-motor-integration.md).

All component records contain exact MPN, LCSC code, datasheet, footprint and
pin-to-net mapping. Reused parts retain their original stock-evidence timestamps.
Reference names are block-local; use `replaces_ref` to merge existing R11/R12/R13,
C9/C10 and J16/J17. Remove J14/J15 and the separate Pololu module in revision B.
`None`/JSON `null` pins 7/20/25 are explicit no-connects, not ground connections.

## Interfaces

- `MOTOR_SUPPLY`: negotiated 20 V branch, assumed steady maximum 21 V; enters RM8.
- `VMOT`: **after** RM8; both driver supplies and all motor bypass/bulk capacitors.
- `+3V3`, `GND`, `STEP` (GPIO18), `DIR` (GPIO19), `MOTOR_RUN` (GPIO23).
- The TEC/feed bus must not pass through RM8. No reverse-blocking diode is fitted
  in this block; the PD designer must specify source sink/backfeed behaviour.
- One fixed 1/16 driver, 0.75 A nominal peak phase current; 0.625 A option by
  fitting the already sourced 1.5 kΩ part at RM4 as well as RM5.

## CAD assets

- [Compact placement handoff](LAYOUT.md), [layout.json](layout.json) and
  [critical-route stubs](critical-routes.json): 13.61 ×15.56 mm core around UM1,
  actual KiCad courtyard/pad checks and selected local copper-clearance checks.
- [motor.kicad_sym](motor.kicad_sym): bare IC symbol, manufacturer pin table,
  exposed-pad CAD number 29. KiCad 9 successfully exported its
  [SVG](symbol-view/A4988SETTR-T_unit1.svg).
- [motor.pretty](footprints/motor.pretty): exact Allegro 3.15 mm EP footprint
  and manufacturer-land HoLRT2512 footprint. Add these as library `motor` when
  integrating, or remap the library prefix explicitly.
- [footprint-checks.json](footprint-checks.json): actual KiCad-loaded pad geometry
  versus reference dimensions. These are library checks, not full-board DRC.
- Thermal vias are deliberately **board layout work**: the footprint specifies
  copper/paste and does not silently install open via-in-pad holes.

## Reproduction (repository root)

```sh
python electronics/revb/motor/design.py
python electronics/revb/motor/make_library.py
python electronics/revb/motor/validate.py
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -v "$PWD/electronics/revb/motor:/work" cat-feeder-kicad:local \
  /usr/bin/python3 /work/check_footprints.py
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -v "$PWD/electronics/revb/motor:/work" cat-feeder-spice:local \
  python /work/simulate_damping.py
```

`check_stock.py` separately retrieves missing new-part public JLC records with
8-second spacing and reuses the frozen revision-A parser read-only. It neither
uploads nor edits supplier projects. Delete only the desired records in this
block's evidence file to request a refresh; old records are timestamped snapshots.

The tests include mutations that ground the charge-pump reservoir incorrectly,
omit the exposed-pad ground, tie reset/sleep high, put bulk capacitance upstream
of damping, select overcurrent values, and weaken the hardware pull-down.

The six ngspice cases reproduce the existing 43.278 V/36.065 V failures and
evaluate the proposed series resistor in the same passive model. The resistor's
high pulse stress is **unqualified**, and regeneration remains an integration
question. Passing these checks is not assembly clearance or physical testing.

[Frozen-file verification](frozen-pcb-check.json) checked all **85** entries in
the existing `electronics/pcb/checksums.json`; every hash matched.
