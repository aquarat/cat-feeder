# Power simulation model contract

This is an operating-envelope study of the **cleared 54-part** controller, not
physical qualification. The runner requires Python standard library + ngspice;
it makes no network calls and installs nothing. Models are regenerated from
explicit checked netlist values/connections. Frozen PCB files are read only.
See [findings and bench priorities](../../../kb/pcb-power-simulation.md).

## Reproduce from repository root

```sh
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -e SIM_IMAGE_ID="$(docker image inspect cat-feeder-spice:local --format '{{.Id}}')" \
  -v "$PWD:/work:ro" -v "$PWD/electronics/sim/power/results:/results" \
  cat-feeder-spice:local python electronics/sim/power/run.py --output /results
```

Create the results directory first if absent. The shared image is built with
`docker build -t cat-feeder-spice:local -f electronics/sim/Dockerfile electronics/sim`.
The entry point also accepts any writable `--output DIR`. Exit 0 means schema,
solver and numerical oracles passed; it does **not** mean circuit PASS.
Nonzero means execution/schema/oracle failure. `summary.json`, row criteria and
`tested_envelope` separately retain engineering failures and conditional claims.

### Completion and failure publication

Each attempt gets a UUID `run_id` (also in provenance) and UTC timestamps.
Before validation or artifact changes, `summary.json` is atomically replaced
with `suite_execution: RUNNING`, `run_state: RUNNING`. Stages are recorded as
work progresses. All JSON publication uses a flushed/fsynced temporary file in
the destination directory and atomic replacement. Only after all required
artifacts, including model hashes, finish is the final summary atomically
published as `suite_execution: PASS`, `run_state: COMPLETE`.

Caught errors explicitly publish `FAIL`/`FAILED` with the failure stage and
return 1; KeyboardInterrupt publishes `FAIL`/`ABORTED` and returns 130. A hard
kill cannot run a handler: its record remains **RUNNING**, meaning incomplete
or interrupted, never evidence of completion. Artifacts may be mixed/partial
until COMPLETE; consumers must gate on the current attempt's run ID and final
status. This output directory is single-writer; use separate output directories
for concurrent runs. Prior successful artifacts are not archived automatically.
If the output medium itself is unwritable, the process still fails, but cannot
guarantee a new failure record; callers must also honor the exit status. UUIDs
and timestamps change on reruns; numerical results remain reproducible.

### Thermal calculation (not SPICE thermal model)

`Pd = (VIN−3.3) Iload + VIN·80µA`; `Tj = Ta + 184 Pd`.
Sweep VIN 4.75/5/5.25 V, Ta 25/40/50°C, total load 200/240/300/500 mA.
Reference θJA = 184°C/W is published SOT25 thermal resistance, **not measured
on this crescent or inside the hot enclosure**. 80 µA is the published maximum
quiescent-current figure; treating it as a constant corner is a study assumption,
not a full-temperature guarantee. Total load includes MCU, driver logic and all
external 3.3V consumers. Input voltage is **at U2** in this calculation.

Use `Ilimit = [(125−Ta)/184 − VIN·80µA]/(VIN−3.3)` for a **125°C target**, not
150°C absolute maximum or shutdown. An additional 1.5% low-VOUT sensitivity is
reported separately, without asserting 25°C accuracy is a full-temperature
limit. Values beyond absolute maximum are algebraic evidence of an unsupported
load, not predicted stable temperature: actual shutdown/foldback is unmodelled.
Steady-state, no thermal time constant, no permitted burst duty inferred.

### U2 behavioral current-pass load steps

The current command is `clamp[10(3.3−Vout), 0, Ilim]` amperes; first-order lag
τ = 2/20/100 µs drives a nonnegative pass current limited by `(VIN−Vout)/0.5Ω`.
This circuit conserves pass-branch current between input and output; quiescent
current is separate. Its finite 10 A/V gain implies 10 mV DC droop at 100 mA.
The load rolls off linearly below 0.5 V to avoid an unphysical negative rail
under current overload; that rolloff is also an assumption. DC node-set hints
assist convergence; actual initial operating-point KCL is independently tested.
**It is not a fitted AP2112 transient response or a worst-case guaranteed bound.**
Loop lag, gain, ESR, dropout law, source impedance and current-limit shape are
chosen sensitivity parameters. No foldback, temperature feedback, shutdown,
reverse conduction, EN ramp, ground bounce or switching noise is claimed.

Grid: source 4.75/5/5.25 V; source R 0.1/2 Ω; capacitance factor 0.3/1;
lag 2/20/100 µs; hard current ceiling 0.6/0.8 A; load 0.1→0.5 A or
0.1→0.7 A, 1 µs edges, step at 200 µs, high for 400 µs. 0.7 A is an intentional
overload beyond guaranteed 600 mA output; 0.8 A ceiling is a sensitivity, not a
guarantee. Passing the assumed 3.0–3.6 V rail criterion remains CONDITIONAL.
Every branch is actually solved in ngspice. Initial KCL and resistive voltage
drop are independently checked for every case. Separate capacitor hold-up test
checks ΔV=ΔIΔt/C without the behavioral controller.

### VMOT RLC/hotplug

Series source/lead R = 0.02/0.1/0.5 Ω, lead L = 0.5/2/10 µH, C10 ESR as above,
source 20/24 V, initially discharged C10, 1 ns connection edge at 10 µs.
This deliberately excites the LC and assumes an ideal source able to deliver
the calculated inrush. Real source current limiting/contact rise or bounce may
change it substantially. No current limit or TVS is invented. High calculated
inrush is not a qualified capacitor/connector surge rating.

The VMOT terminal is capacitor voltage **plus ESR·current**, not just ideal
capacitor voltage. Each entire trace is compared to the independently coded
closed-form under/overdamped series RLC response (source-step midpoint), requiring
max voltage disagreement <0.2% of VIN. A lossless LC test checks 2·VIN peak and
π√LC time independently to 5 mV/0.1 µs. No-load high-Q case omits the small
110 kΩ divider load and unknown purchased carrier ceramics; it is not a board
parasitic extraction. Fast local ringing, motor regeneration and source
disconnection are **not bounded by this study**. <35 V is CONDITIONAL, ≥35 V FAIL
against the A4988 maximum. 50 V C10 does not protect the 35 V IC.

`results/models/*.cir` and `.log` retain every solver input and log. Representative
full waveforms are gzip-compressed `.dat.gz`; CSVs contain every case's metrics.
`model-hashes.json` fingerprints generated models; `provenance.json` records
runner/source hashes, Python/ngspice versions and supplied Docker image ID.
Both retained VMOT reruns use the same log/schema/finite/end-time/time-order
validator as first solves, discard stale raw data before invocation, and check
their peak voltage and current against the first solve to 1e-9 relative/absolute
tolerance before compression.
`vmot-worst.svg` plots retained raw solver output. Tests of the oracle limits,
schema mutation rejection, actual invalid-SPICE rejection and nonzero top-level
failure reporting are in `test_run.py`; reproduce with the same Docker command
but `python electronics/sim/power/test_run.py --output /results`. Its **12 test
methods** include full actual-solver runs with late model-hash publication failure,
late final-summary publication failure, and SIGKILL just before final publication.
Other tests exercise KeyboardInterrupt, atomic-replace failure, an unwritable
failure report, six zero-exit invalid/stale retained-output variants, and retained
peak disagreement. Intentional failure diagnostics on stderr are expected;
`test-integrity.log` records whether the error paths behaved correctly.
